# 景品ルーレット Plus

[景品ルーレット](https://github.com/nao0310/prize-roulette) をもとに、**景品の設定・受付・名簿の管理をすべてサイト上でできる**ようにしたバージョンです。ルーレットの見た目と抽選の仕組みはそのままです。

- 公開ページ: https://nao0310.github.io/prize-roulette-plus/
- サーバー不要・無料・インターネットに送信しない作りです。`index.html` をダウンロードしてダブルクリックすれば、ネットがなくても動きます。
- PC・タブレット・スマホ（縦・横）に対応しています。

## 画面の構成

上のタブで切り替えます。

| タブ | できること |
|---|---|
| 🎡 抽選 | ルーレットで当選番号を抽選（下位から順に、最後が1位）。発表モード、回し直し、リザルト |
| 🎁 景品 | 景品の順位と中身を入力・修正、▲▼で入れ替え、追加（1位に／最下位に）、まとめて追加、削除。Excel・CSVの読み込み、CSVの書き出し |
| 🙋 受付 | 来た人が名前を入力すると「あなたの番号は ○ 番です」と表示。受付モード（全画面）で受付用の端末として使える |
| 📋 名簿 | 受付の設定（番号の振り方・最初の番号・最大人数・受付の開始/終了・名前の表示）、手で追加、名前の修正・削除、検索、CSVの読み込み・書き出し |
| 💾 データ | 抽選結果・景品・名簿のCSV書き出し、まるごとバックアップと復元、この端末のデータの全削除 |

## 当日の流れ（例）

1. **準備**：「景品」タブで景品を入力。「名簿」タブでイベント名と番号の振り方を決める
2. **受付**：受付用の端末（PCかタブレット）で「受付」タブ →「受付モードを始める」。来た人が名前を入れて「番号をもらう」を押すと、番号が大きく表示されます
3. **抽選用のPCに移す**（受付と抽選が別の端末のとき）：受付の端末で「データ」→「バックアップを書き出す」、抽選用のPCで「バックアップから戻す」
4. **抽選**：「抽選」タブ →「発表モード」。受付した人の番号だけで抽選し、当選画面に名前（またはニックネーム）を表示します
5. **後片付け**：「データ」で抽選結果をCSVに書き出し、共用のPCなら「すべて消す」

## 受付の機能

- **名前は任意**：「名前」「ニックネーム」「入力しない」から選べます。入力しない人は番号だけで参加し、当選しても名前は表示されません
- **番号の振り方**
  - 来た順：1, 2, 3 … と順番に（最初の番号を 101 などにもできます）
  - ランダム：「最初の番号」から「最大人数」の範囲で、空いている番号からランダムに
  - 満員になったら「スタッフにお声がけください」と表示します。名簿画面から番号を指定して手で追加することもできます
- **同じ名前の確認**：同じ名前ですでに受付している人がいると「別の方ですか？」と確認します（ほかの人の番号は表示しません）。空白の有無や全角・半角の違い（「山田 太郎」と「山田太郎」など）も同じ名前とみなします
- **受付モード**：全画面になり、来た人がほかの画面に移れなくなります。終了は右下の「スタッフ」ボタンを **2秒長押し**。ページを再読み込みしても受付モードのままです（全画面はブラウザの仕組み上、自動では戻らないので、必要ならスタッフが全画面に戻してください）
- **受付の終了**：名簿画面で「受付中」をオフにすると、受付画面に「受付は終了しました」と出ます
- **途中参加**：名簿を使っているときは、抽選の途中でも受付・追加ができ、次の抽選から対象になります
  - 下位から抽選していて、景品が名簿の人数より多いときは、増えた人の分だけ抽選する景品も増えます。次の景品が下の順位に戻るので、「参加者が増えたので、○位も抽選します」と表示します
  - 名簿を使わず（参加人数の 1〜○番で）抽選を始めたあとは、リセットするまで受付・手での追加はできません（途中から名簿ができると、抽選の対象が名簿の人だけに変わってしまうため）

## 抽選のルール

- 名簿に1人でもいるときは、**名簿にいる番号だけ**で抽選します。名簿が空なら「抽選」タブの参加人数（1〜○番）で抽選します
- 景品が名簿の人数より多いときは、上位の景品から人数分だけ抽選します
- 抽選は番号だけで行い、名前は表示にだけ使います。当選しやすさは全員同じです（ブラウザの暗号用乱数 `crypto.getRandomValues` を使用）
- 抽選の途中は、景品の並べ替え・追加・削除はできません（景品名の修正はできます）。「抽選」タブのリセットで解除できます
- 当選した人は名簿から削除できません。当選者がいないときは「回し直し」を使います
- 抽選の途中で、景品の数が参加者の数以上のときは、名簿から人を削除できません（番号が足りなくなり、最後の景品を抽選できなくなるため）
- 当選番号はルーレットを回し始めた時点で決まっています。回っている途中でページを再読み込みしても引き直しにはならず、その番号で当選画面を出します
- リセットの確認画面では、当選があるときに「抽選結果をCSVで書き出す」ボタンを出します。結果が必要なら、リセットの前に書き出してください

## CSVの形式

書き出したCSVは Excel でそのまま開け、読み込み直すこともできます（UTF-8 / Shift_JIS どちらも可）。読み込み直すときは、数式対策で付けた先頭の `'`（下の「セキュリティとデータの扱い」）を外して元の名前に戻します。

| ファイル | 列 |
|---|---|
| 景品 | 順位, 景品名, 当選番号, 名前 |
| 名簿 | 番号, 名前, 種別（名前／ニックネーム／入力しない）, 受付時刻, 当選 |
| 抽選結果 | 抽選した順, 順位, 景品名, 当選番号, 名前（＋当選者なしで外した番号） |

- 景品のファイルは、1行目に「順位」「景品名」などの見出しがあればその列を、なければA列=順位・B列=景品名として読みます。見出しに順位の列がないときは、上の行から順に1位、2位…とします
- セルは書いてあるとおりの文字で読みます（「3/4」や「0012」が日付や数字に変わることはありません）

サンプル: [`sample-prizes.xlsx`](sample-prizes.xlsx)（景品）、[`sample-roster.csv`](sample-roster.csv)（名簿・架空の名前）

## セキュリティとデータの扱い

**入力した名前・景品・抽選結果が外部に送られることはありません。**

- **通信しない作り**：ページに必要なもの（Excel読み込み用のプログラム、フォント、アイコン）はすべて同梱し、外部から何も読み込みません。さらにブラウザのセキュリティ機能（Content Security Policy の `connect-src 'none'` など）で、インターネットへの通信そのものを禁止しています
- **保存はその端末だけ**：データはブラウザの保存領域（localStorage）にだけ保存され、ほかの端末やほかの人には共有されません。元の「景品ルーレット」とも別の保存場所を使います
- **同じ端末の2つのタブ**：受付用と抽選用など、同じ端末で2つのタブを開いているときは、片方で変えた内容がもう片方にすぐ反映されます（互いに上書きしません）
- **名前は任意・表示も選べる**：受付で名前を入れない選択ができ、名簿画面で「名前を表示する」をオフにすると、会場の画面には番号だけが出ます
- **受付画面でほかの人の情報を見せない**：同じ名前の確認でも、ほかの人の番号は表示しません。受付モード中は名簿画面に移れません
- **CSVの安全対策**：書き出すとき、`=` `+` `-` `@` で始まる値の先頭に `'` を付け、Excelで開いたときに数式として実行されないようにしています（CSVインジェクション対策）
- **画面への表示**：名前や景品名に記号やタグが入っていても文字として表示し、プログラムとして実行されることはありません
- **後片付け**：「データ」→「すべて消す」で、この端末のデータを完全に消せます。共用のPCで使ったあとは実行してください
- **書き出したファイルの扱い**：名簿・抽選結果のCSVやバックアップには名前が入ります。共有するときは扱いに注意してください。**実際の名簿や景品リストはこのリポジトリに入れないでください**（公開リポジトリは誰でも見られます）

## テスト

[Playwright](https://playwright.dev/) と Chromium で、実際に画面を操作して確かめるテストです（Node.js 18 以降、`playwright` パッケージが必要）。ローカルサーバーと `file://` の両方で実行します。

```bash
sh tests/run.sh
```

- 抽選・公平性（当選番号の偏りをカイ二乗検定で確認。回数は `FAIR_ROUNDS=4000 sh tests/run.sh` のように変えられます）・名簿・受付・景品の編集・ファイルの読み書き・セキュリティ・表示（PC／iPad／iPhone）・保存領域を確かめます
- 1つのファイルだけ実行するとき：`MODE=file node --test tests/reception.test.js`（`MODE=http` でローカルサーバー）
- `SHOT_DIR=フォルダ` を付けると、表示のテストでスクリーンショットを保存します
